Subject: Decision on D²RO Manuscript and Recommendations Before Resubmission

Dear Polla,

Thank you for the substantial effort you put into revising the D²RO manuscript. I reviewed the latest version carefully, including the newly public GitHub repository, the experimental scripts, raw CSV files, plotting code, and baseline implementations.

Unfortunately, my recommendation at this stage is **rejection in the current form, with encouragement to resubmit as a new manuscript after the experimental evaluation has been rebuilt properly**.

I want to emphasize that this decision is **not primarily about the novelty anymore**. The revised paper does a much better job of explaining the contribution as a distributed, time-varying graph-cost framework with anticipatory edge-cost propagation, effective sensing-horizon extension, and a directional bottleneck reservation protocol. That part has improved considerably and is now much more defensible scientifically.

The main reason for rejection is the experimental evidence.

The most serious issue is that several studies presented in the manuscript as N = 100 Monte Carlo simulation experiments are not actually generated by running the corresponding simulations. In the public experiment code, the ablation, cross-domain, and scalability studies use predetermined base values and then add random perturbations around those values. For example, the ablation study directly assigns values around 14.6 s for full D²RO, around 21.4 s without mesh communication, predetermined discomfort values, and probabilistic success/failure rates. Likewise, the cross-domain and scalability studies start from fixed expected makespans, packet counts, replan latencies, and other metrics, and then generate noisy samples around them. These datasets are therefore synthetic result generators rather than outputs of actual Monte Carlo robot simulations.

Because these generated datasets are then used in the paper as experimental evidence, the associated confidence intervals, p-values, ablation conclusions, cross-domain generalization claims, and scalability claims cannot currently be considered valid empirical results.

Before thinking about resubmission, I strongly recommend that you do the following:

1. **Remove all synthetic result generation from the experimental pipeline.** Every row in every CSV described as an experimental result must come from an actual execution of the corresponding simulation condition.

2. **Run every claimed experiment genuinely.** If the manuscript claims 100 trials for five algorithms, five ablation configurations, three environments, and multiple scalability settings, then those simulations should actually be executed under controlled seeds and their raw outputs saved.

3. **Rebuild the ablation study properly.** The full D²RO system and each ablated version should execute the same environment, initial conditions, seeds, pedestrian behaviors, robot configurations, and stopping criteria. The only change should be the component being removed. Do not generate expected outcomes manually.

4. **Rebuild the cross-domain evaluation using the actual supermarket, hospital, and airport simulators.** The reported makespan, V2V packets, replan counts, social violations, and success rates should all be measured from those simulations rather than initialized from expected values.

5. **Rebuild the scalability study using actual simulations.** For crowd-density experiments, keep fleet size fixed and genuinely simulate each human-density level. For fleet-size experiments, keep crowd size fixed and genuinely simulate each robot-fleet size. The resulting curves should emerge from the system rather than being predefined.

6. **Validate the baselines independently.** The ORCA implementation in particular requires careful checking. The current implementation appears to pass each agent's own position inside the peer-position list, which may cause the robot to treat itself as an obstacle. The relative-velocity calculation for peer agents also needs verification. ORCA, APF, Static A*, and Decentralized Local MAPF should be implemented faithfully and tested against simple reference scenarios before using them for comparative claims.

7. **Use the same measurement procedure for computational timing across all algorithms.** At present, D²RO timing is measured using `time.perf_counter()`, while several baseline latency values appear to be assigned as constants. All timing results must be measured, ideally over many repetitions with warm-up and clearly documented hardware/software specifications.

8. **Generate every table and figure automatically from the final raw experimental CSV files.** There should be a single source of truth. The manuscript should not contain manually entered values that can drift away from the data. This is particularly important because Figure 7 is still inconsistent with Table II in the current PDF.

9. **Regenerate Figure 7 and audit all remaining figures.** The success-rate, makespan, and proxemic-violation values in the figure must exactly match the final dataset and the table. The remaining internal figure-number labels should also be cleaned up.

10. **Recompute all statistical analyses from the genuine data.** Confidence intervals, standard deviations, hypothesis tests, p-values, and effect sizes should be calculated only after the real experiments have been completed. Statistical testing should not be performed on values generated around predetermined means.

11. **Document the experimental protocol completely.** State the random-seed policy, number of agents, start/goal generation, pedestrian behavior, velocities, loitering probabilities, graph sizes, map dimensions, timeout conditions, communication latency/loss assumptions, and all algorithm parameters.

12. **Audit the central cost formulation and weights.** The current paper now defines the weighted cost more clearly, which is good. For resubmission, explain how the weights were selected and preferably include a sensitivity analysis or tuning procedure so that the values do not appear arbitrary.

13. **Keep the novelty framing introduced in the latest revision.** The strongest part of the revised paper is now the distributed anticipatory edge-cost propagation idea. I recommend keeping the paper centered around:

* distributed propagation of time-decayed edge costs;
* effective sensing/planning-horizon extension beyond local perception;
* directional bottleneck reservation;
* socially and kinematically conditioned incremental replanning.

This is much stronger than presenting the work simply as a combination of five existing components.

14. **Be cautious with theoretical language.** Continue using wording such as “empirically eliminated deadlocks across all evaluated trials” unless you provide a formal theorem under explicit assumptions. Avoid unconditional claims such as “provably deadlock-free” unless a real proof is included.

15. **Synchronize the manuscript and GitHub repository.** The README, code, CSV files, plots, paper, and reported results should all describe the same experimental version. At present, some repository documentation still refers to older numbers and earlier experimental configurations.

16. **Tag the exact source-code version used for the resubmission.** Ideally create a release or commit tag such as `paper-v2-experiments` and state that commit or release in the manuscript. A reviewer should be able to check out that version and reproduce the tables and figures.

17. **Resolve all remaining citation and bibliography issues.** The manuscript still contains an unresolved `[?]` citation for HA-VLN 2.0. Every reference should be checked against the original publication for authors, title, venue, year, pages, and DOI where available.

18. **Do not reuse the current generated experimental results after rewriting the simulator.** Once the methodology is corrected, rerun everything from scratch and allow the results to be whatever the simulations actually produce. If the real experiments show smaller improvements, lower success rates, or larger variances than the present manuscript, report those honestly. A believable 93% success rate supported by real experiments is scientifically much stronger than a synthetic 100% result.

My suggestion would be not to rush another submission. The conceptual side of the work is now promising enough that it is worth taking the time to rebuild the validation properly. The next version should be treated almost as a new experimental study built around the improved D²RO formulation.

If the genuine simulations continue to demonstrate that anticipatory V2V cost propagation reduces deadheading, that the reservation mechanism reduces bottleneck conflicts, and that the socially weighted planner improves human-space compliance, then I believe the work could become a much stronger and more credible submission.

For that reason, my recommendation is **reject in the present form, but resubmission is encouraged after a complete reconstruction and rerun of the experimental evaluation**.

Best regards,

Tantoon
